Now that the Forecast Request workflow is ready, connect Forecast Requests tightly with Owners, Properties, and Revenue Forecasts.

The objective is to eliminate duplicate data entry.

When a Revenue Manager reviews a Forecast Request, they should be able to:

1. Review the submitted request
2. Match or create the Owner
3. Match or create the Property
4. Confirm or amend submitted data
5. Create the Forecast using the same request data
6. Preserve a clear link back to the original Forecast Request

Do not require the Revenue Manager to manually retype information that already exists in the request.

==================================================
1. CORE RELATIONSHIPS
==================================================

Extend ForecastRequest with:

ownerId nullable
propertyId nullable
forecastId nullable

assignedRevenueManagerId nullable

convertedAt nullable
convertedByUserId nullable

Also store:

sourceRequestReference
requestVersion / snapshot if needed

Recommended relationships:

ForecastRequest
→ Owner
→ Property
→ Forecast

One Forecast Request should normally result in:

- one Owner record
- one Property record
- one Forecast record

However, Owner and Property may already exist.

Therefore support:

- Link Existing Owner
- Create New Owner
- Link Existing Property
- Create New Property

25. DUPLICATE PREVENTION
==================================================

Before creating Owner:

Search for likely duplicate.

Before creating Property:

Search for likely duplicate.

Warnings should be non-blocking but clear.

Owner duplicate signals:

- same mobile
- same email
- very similar name

Property duplicate signals:

- same owner
- same building
- same unit number

If exact property match exists:

Recommend:
Link Existing Property

instead of creating duplicate.

==================================================
30. FINAL ACCEPTANCE CRITERIA
==================================================

This integration is complete when:

1. Forecast Requests link to Owner, Property, and Forecast records.
2. Revenue Manager can link an existing Owner.
3. Revenue Manager can create Owner directly from Request.
4. Owner form is prefilled from Request.
5. Owner page shows Forecast Request Context bar only when linked.
6. Revenue Manager can link an existing Property.
7. Revenue Manager can create Property directly from Request.
8. Property form is prefilled from Request.
9. Property page shows Forecast Request Context bar only when linked.
10. Uploaded Request media is available in Property creation.
11. Proposed PMC flows into Forecast.
12. Referee flows into Forecast.
13. Revenue Manager assignment flows into Forecast.
14. Original Forecast Request remains immutable.
15. User can compare submitted versus final values.
16. Duplicate Owner checks exist.
17. Duplicate Property checks exist.
18. Forecast cannot be marked Converted before Forecast record exists.
19. Forecast shows its source Forecast Request.
20. Revenue Manager never has to retype request data manually.
